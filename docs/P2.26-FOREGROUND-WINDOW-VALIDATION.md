# P2.26 — Foreground/window validation

## Safety contract

A captured frame is eligible for AI processing only while the Accessibility service remains connected and the active Accessibility root still belongs to the exact target package and the same active application window.

The policy fails closed when any of the following is true:

- service generation is disconnected or stale;
- snapshot package differs from the configured target;
- active root is missing or belongs to another package;
- the root window ID cannot be matched to an active Accessibility window;
- matched window package, type, or active state is invalid.

## Enforcement points

Validation is repeated at event ingestion, before screenshot capture, after screenshot callback and before inference, after inference before authorization, during live-node lookup, and immediately before ACTION_CLICK.

A foreground/window rejection never authorizes a click. Existing screenshot single-flight, latest-frame coalescing, one-second capture throttle, freshness, live node matching, protected-target veto, and native inference ownership remain in force.

## Verification boundary

Unit tests cover the pure validation policy. CI compilation and unit tests do not replace device validation; device testing remains deferred by request.
