# P2.17 — Autonomous AI → Accessibility

## Current implementation

P2.17 now contains the end-to-end application wiring for local Qwen3-VL inference:

- `ModelPackageImporter` imports a ZIP into app-private storage and validates the manifest, file sizes, SHA-256 digests, and GGUF magic before replacing an installed model.
- The dashboard exposes a system document picker for the model ZIP.
- llama.cpp is pinned to upstream commit `56381e407c0ccfb3a6f71e668a27a901001d22ce` and its source archive is verified before the native build.
- CMake builds the llama.cpp `llama`, `llama-common`, and `mtmd` components plus the app JNI bridge for `arm64-v8a`.
- `LlamaCppQwen3VlRuntime` sends the screenshot and bounded Accessibility metadata to the local model and parses the structured response.
- The Accessibility service sends the screenshot directly to the AI decision engine. The legacy OCR action-selection pipeline and ML Kit runtime dependency have been removed.
- Only a validated AI `NEXT_AD` or `CLOSE` decision is passed to the live Accessibility node matcher and click executor.

**Verification status:** implementation and tests are committed to the feature branch, but the native Android CI build and physical-device inference have not yet been confirmed. Do not treat the feature as production-ready until CI passes and Qwen3-VL is loaded and tested on the target phone.

## Model package format

Create a ZIP containing exactly these three root entries (no enclosing folder):

- `manifest.properties`
- `model.gguf` — Qwen3-VL-2B-Instruct language model
- `mmproj.gguf` — matching Qwen3-VL vision projector

The manifest must contain:

```properties
format=smart-ad-skip-qwen3-vl
version=1
model.file=model.gguf
model.size=SIZE_IN_BYTES
model.sha256=64_HEX_SHA256
mmproj.file=mmproj.gguf
mmproj.size=SIZE_IN_BYTES
mmproj.sha256=64_HEX_SHA256
```

The two SHA-256 values must be computed over the exact GGUF files placed in the ZIP. The importer rejects unknown or duplicate entries, path traversal, missing files, oversized entries, invalid manifest values, hash mismatches, unsupported GGUF versions, and non-GGUF payloads. The active model is replaced only after both files pass validation. These package-local hashes detect corruption or mismatch; they do not prove publisher authenticity unless the expected hashes are obtained from a separately trusted source.

## Decision contract

The model is the only action selector. It may independently return `NEXT_AD`, `CLOSE`, or `WAIT`. The prompt treats screen text as untrusted content and restricts actionable targets to the supplied visible, enabled, clickable Accessibility elements.

Expected JSON:

```json
{
  "action": "NEXT_AD | CLOSE | WAIT",
  "targetElementId": "node-id-or-null",
  "confidence": 0.0,
  "rationale": "short explanation"
}
```

Malformed output, unavailable model, inference exceptions, low confidence, stale frame, wrong package, missing/duplicate target, or invalid bounds all resolve to `WAIT`.

## Shared execution-integrity checks

AI chooses the action; the executor does not reinterpret or substitute it. The following checks remain mandatory before any device action:

1. Target package is `com.funnyvideo.cgame.fruitblast`.
2. Screenshot and Accessibility snapshot are fresh (maximum AI frame age: 1.5 seconds).
3. Model confidence is finite and at least 0.85.
4. The returned target ID resolves to exactly one supplied Accessibility element.
5. The target is visible, enabled, clickable, and within the screenshot bounds.
6. A fresh live Accessibility tree contains one unique matching node.
7. Existing duplicate-attempt protection remains active.
8. The shared policy continues to deny actions in a known completed-ad context.
9. A protected-label veto blocks known reward, install, purchase, continue, and external-navigation targets without selecting a replacement action.

No OCR/rule-based fallback is permitted when the model is missing, loading, unavailable, or uncertain. The Android Accessibility permission remains an OS-level prerequisite.

## Build and CI

The P2.17 GitHub Actions workflow installs JDK 17, Android SDK 36, NDK 27.2.12479018, and CMake 3.22.1; fetches and verifies the pinned llama.cpp archive; runs unit tests; assembles the arm64 debug APK; and uploads the APK artifact.

## Device validation still required

- Confirm the target phone is `arm64-v8a` and has enough free memory/storage for the Qwen3-VL-2B model and projector.
- Import the model ZIP through the dashboard.
- Enable the Accessibility service and open Fruit Blast.
- Verify model readiness and local inference logs.
- Confirm AI-only `WAIT`, `NEXT_AD`, and `CLOSE` decisions against real screens.
- Confirm all denied/ambiguous cases remain `WAIT` and no OCR fallback is invoked.

No physical-device test result is claimed by this PR.
