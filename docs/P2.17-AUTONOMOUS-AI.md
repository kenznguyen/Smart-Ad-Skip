# P2.17 — Autonomous AI Ad Interaction

## Intent

Move action selection from OCR/pixel heuristics and the legacy Click Authorization policy
to a Qwen3-VL decision engine. The model may independently choose `NEXT_AD`, `CLOSE`,
or `WAIT`. Strategy/Core heuristics do not veto or manufacture model decisions.

## Local model runtime

The selected deployment is on-device Qwen3-VL, initially targeting the 2B Instruct
variant through a native multimodal runtime (llama.cpp MTMD). Model weights and the
vision projector must be imported into app-private storage; they must not be bundled in
the APK. The runtime must expose readiness and image+prompt inference through
`Qwen3VlRuntime`.

**Integration status:** this PR adds and tests the AI decision contract and policy boundary.
It does not yet include the native llama.cpp/MTMD binary, model importer, or a production
`Qwen3VlRuntime` implementation. Consequently it must not be represented as end-to-end
Qwen3-VL inference or enabled for automatic device actions yet. The service remains on
the existing P2.16 path until the native runtime is delivered and device-tested.

## Decision contract

The model response is structured as:

```json
{
  "action": "NEXT_AD | CLOSE | WAIT",
  "targetElementId": "element-id-or-null",
  "confidence": 0.0,
  "rationale": "short explanation"
}
```

The engine rejects stale frames, non-target packages, missing/ambiguous targets,
out-of-screen or non-clickable targets, invalid confidence, and inference failures.
These are execution-integrity checks, not a second action-selection strategy. No
heuristic fallback is permitted when the model is unavailable.

## Next implementation gate

1. Pin a Qwen3-VL-capable llama.cpp revision and build the Android arm64-v8a MTMD JNI
   bridge with NDK/CMake.
2. Add verified model-package import (manifest, SHA-256, GGUF and mmproj validation).
3. Connect screenshot + accessibility context to the local runtime and parse constrained
   structured output.
4. Route only model decisions to the Accessibility executor; remove the legacy
   ActionExecutionPolicy from that path.
5. Add native build CI and test on a physical Fruit Blast device before enabling actions.

## Safety and scope

The AI is the sole decision-maker for whether to wait, close, or advance. The executor
does not reinterpret that choice. Android Accessibility permission remains an OS-level
prerequisite. Frame freshness, package scoping, valid coordinates, and duplicate-action
prevention remain execution-integrity constraints.
