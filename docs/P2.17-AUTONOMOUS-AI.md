# P2.17 — Autonomous AI → Accessibility

## Current implementation

P2.17 now contains the end-to-end application wiring for local Qwen3-VL inference:

- `ModelPackageImporter` imports a ZIP into app-private storage and validates the manifest, file sizes, SHA-256 digests, and GGUF magic before replacing an installed model.
- The dashboard exposes a system document picker for the model ZIP.
- llama.cpp is pinned to upstream commit `56381e407c0ccfb3a6f71e668a27a901001d22ce` and its source archive is verified before the native build.
- CMake builds the llama.cpp `llama`, `llama-common`, and `mtmd` components plus the app JNI bridge for `arm64-v8a`.
- `LlamaCppQwen3VlRuntime` sends the screenshot and bounded Accessibility metadata to the local model and parses the structured response.
- The Accessibility service sends the screenshot directly to the AI decision engine. The legacy OCR action-selection pipeline and ML Kit runtime dependency have been removed.
- Only a validated AI `NEXT_AD` or `CLOSE` decision is passed to the live Accessibility node matcher and click executor.

**Verification status:** unit tests and the native Android CI build passed (P2.17 Android CI run #79). The generated arm64-v8a APK was inspected and contains libsmartadskip_qwen.so. Physical-device model loading and Fruit Blast interaction have not yet been confirmed; do not treat the feature as production-ready until that test passes.

## Model package format

Create a ZIP containing exactly these three root entries (no enclosing folder):

- `manifest.properties`
- `model.gguf` — Qwen3-VL-2B-Instruct language model
- `mmproj.gguf` — matching Qwen3-VL vision projector

The manifest must contain:

```properties
format=smart-ad-skip-qwen3-vl
version=1
model.file=model.gguf
model.size=SIZE_IN_BYTES
model.sha256=64_HEX_SHA256
mmproj.file=mmproj.gguf
mmproj.size=SIZE_IN_BYTES
mmproj.sha256=64_HEX_SHA256
```

The two SHA-256 values must be computed over the exact GGUF files placed in the ZIP. The importer rejects unknown or duplicate entries, path traversal, missing files, oversized entries, invalid manifest values, hash mismatches, unsupported GGUF versions, and non-GGUF payloads. The active model is replaced only after both files pass validation. These package-local hashes detect corruption or mismatch; they do not prove publisher authenticity unless the expected hashes are obtained from a separately trusted source.

## Decision contract

The model is the only action selector. It may independently return `NEXT_AD`, `CLOSE`, or `WAIT`. The prompt treats screen text as untrusted content and restricts actionable targets to the supplied visible, enabled, clickable Accessibility elements.

Expected JSON:

```json
{
  "action": "NEXT_AD | CLOSE | WAIT",
  "targetElementId": "node-id-or-null",
  "confidence": 0.0,
  "rationale": "short explanation"
}
```

Malformed output, unavailable model, inference exceptions, low confidence, stale frame, wrong package, missing/duplicate target, or invalid bounds all resolve to `WAIT`.

## Shared execution-integrity checks

AI chooses the action; the executor does not reinterpret or substitute it. The following checks remain mandatory before any device action:

1. Target package is `com.funnyvideo.cgame.fruitblast`.
2. Screenshot and Accessibility snapshot are fresh (maximum AI frame age: 1.5 seconds).
3. Model confidence is finite and at least 0.85.
4. The returned target ID resolves to exactly one supplied Accessibility element.
5. The target is visible, enabled, clickable, and within the screenshot bounds.
6. A fresh live Accessibility tree contains one unique matching node.
7. Existing duplicate-attempt protection remains active.
8. The shared policy continues to deny actions in a known completed-ad context.
9. A protected-label veto blocks known reward, install, purchase, continue, and external-navigation targets without selecting a replacement action.

No OCR/rule-based fallback is permitted when the model is missing, loading, unavailable, or uncertain. The Android Accessibility permission remains an OS-level prerequisite.

## Frame integrity and bounded inference

- Each screenshot request receives a monotonically increasing frameId. The screenshot JPEG and Accessibility elements are assembled into one immutable AdFrameContext using that same ID and the event snapshot timestamp.
- Frames are resized to the configured maximum edge before JPEG encoding and JNI/MTMD. Accessibility bounds remain in original screen coordinates and are transformed into the resized-image coordinate space only when constructing the prompt.
- Screenshot capture is single-flight. The native inference executor has one worker and no pending queue; overlapping submissions are rejected as WAIT, so stale frames cannot accumulate behind a slow inference.
- Inference has a configurable deadline (default 12 seconds). JNI inference is synchronous and cannot be safely force-stopped mid-kernel; the coroutine deadline returns WAIT immediately, and any late native result is discarded. The worker remains occupied until JNI returns, and new work is rejected rather than queued.
- CPU threads, context size, batch size, image edge, and timeout are validated configuration values. Defaults (2 threads, context 2048, batch 256, image edge 960) are conservative starting points, not device-optimized claims.
- Immediately before performAction, the executor checks that the original request is still current, the snapshot is still fresh, the package is correct, and a unique visible/enabled/clickable live node still matches. Any mismatch or exception denies the click.

Unit tests cover timeout-to-WAIT, invalid frame identity, and runtime parameter validation. Physical-device latency, memory, thermal behavior, and native timeout behavior still require measurement on the target phone.


## Dashboard telemetry

The Dashboard observes a process-local read-only AiRuntimeDashboardStatus state flow:
- Runtime lifecycle: NOT_IMPORTED, LOADING, READY, FAILED, STOPPED.
- Active inference parameters: CPU threads, context, batch, image edge, timeout, confidence and frame-age thresholds.
- Latest model output: action, WAIT/decision reason, frame ID, observation time, and aggregate model decision counts.
- Model action suggestions are explicitly not reported as confirmed clicks. The shared risk checks and live Accessibility-node gate remain the only click authorization path.
- If a package is imported while Accessibility is already connected but the runtime has not loaded it, the Dashboard requests a service reconnect instead of displaying READY.


## P2.17.1–P2.17.3 lifecycle and target hardening

- JNI load, inference, and destruction are serialized on one dedicated native executor. Service teardown only marks the runtime unavailable and queues native destruction; it never waits for JNI on Android's main thread.
- Inference is single-flight. A timeout or coroutine cancellation cannot interrupt native code, so its result is discarded; a close request is queued behind an active native call, and queued work checks the close flag before entering JNI.
- Dashboard transitions to FAILED on a native inference failure and STOPPED when the Accessibility service unbinds or is destroyed. Telemetry never grants click permission.
- Targets without an Accessibility text/content-description label are denied. Symbol labels are accepted only for their matching action (for example, `>>` for NEXT_AD and `X` for CLOSE); protected labels remain vetoed.
- The live Accessibility node must retain semantic identity. A missing label, changed label, disabled/invisible node, ambiguous match, stale frame, or failed final authorization results in no click.
- Regression coverage includes serialized close during inference, failed native load, post-close inference rejection, timeout handling, unlabelled/changed live targets, and Dashboard failure state.


## P2.18 — Screenshot throttle

- Android screenshot requests are gated to a minimum 1,000 ms interval using monotonic elapsed-realtime timestamps.
- The throttle is acquired only after the existing single-flight lifecycle token, so concurrent events cannot consume the interval or overlap capture.
- Rejected burst events are coalesced by dropping duplicate capture attempts; they never reach inference and never authorize a click.
- Requests accepted by Android, including requests that later fail through `onFailure`, retain the interval. A synchronous exception thrown before request acceptance rolls back only that request's reservation. Service reset clears both the in-flight lifecycle and throttle state.
- A throttle rejection is logged as `capture_throttled_min_interval`; Android capture errors remain fail-closed.
- Unit tests cover the first request, sub-interval rejection, exact-boundary acceptance, non-starvation, and lifecycle reset.
- The existing AI selection, freshness, protected-target veto, live-node identity, and final Click Authorization policies are unchanged.


## P2.19 — Screenshot failure diagnostics

- Synchronous exceptions thrown while submitting `takeScreenshot()` are logged with the exception class and a whitespace-normalized, length-limited message.
- Android callback failures remain separately identified by `capture_failed_code=<errorCode>`; synchronous submission failures use `capture_request_failed exception=<type> message=<message>`.
- A synchronous submission failure releases only the matching throttle reservation because Android did not accept that request. A stale failure cannot release a newer reservation.
- Failures reported asynchronously by Android continue to consume the 1,000 ms interval, avoiding rapid retries after a submitted request.
- The request remains fail-closed: no screenshot processing, inference, or click path is entered after a synchronous submission exception.
- Regression tests cover exception type/message propagation, failure-handler isolation, reservation rollback, and protection against stale rollback.
- No changes to the 1,000 ms interval, AI action selection, freshness checks, protected-target veto, live-node identity, or final Click Authorization.
