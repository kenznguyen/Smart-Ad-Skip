# P2.33 – Deterministic Binder Fault Injection

## Scope

Adds an instrumentation-only Messenger endpoint registered in the androidTest APK. The endpoint can hold a request reply and release it only when the test sends an explicit command. This gives the test control over callback ordering without depending on arbitrary sleeps.

## Coverage

- **Late callback after reconnect:** hold generation N's response, advance the expected generation to N+1, release N, and assert NativeProcessSessionPolicy rejects it.
- **Timeout concurrent with reconnect:** allow the old request's bounded wait to expire while its remote reply remains held; release the old reply after generation advances; then prove a request on the new generation still receives its response.
- **Watchdog termination authorization race:** verify an old watchdog snapshot cannot authorize termination after reconnect, even when PID/session/start-time fields otherwise match; verify a complete matching current identity remains eligible.

The existing NativeInferenceProcessServiceInstrumentedTest separately exercises real isolated-process death and Android's automatic Binder reconnect.

## Run

```bash
gradle :app:connectedDebugAndroidTest
```

Run on an ARM64 Android device or emulator with API 26+. Hosted CI compiles the instrumentation APK; it does not execute these device tests unless an Android device is attached.

## Boundaries

The fault endpoint deterministically controls Messenger reply delivery. The timeout test models the caller's timed wait and checks the generation boundary; it does not force the production proxy's private timeout scheduler. The watchdog test validates the exact production NativeProcessSessionPolicy.mayTerminate gate, but does not invoke the private watchdog thread or issue a real kill concurrently with reconnect. No production IPC or watchdog behavior is changed by this test-only phase.
