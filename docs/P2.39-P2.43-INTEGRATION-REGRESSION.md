# P2.39–P2.43 Integration and Regression Validation

Branch: `feature/p2-17-autonomous-ai-ad-interaction`

## Implemented behavior

- **P2.39 – Window snapshot distinction:** `getWindows()` retrieval distinguishes AVAILABLE, confirmed EMPTY, and FAILED. EMPTY can use a verified `rootInActiveWindow` for capture only; FAILED rejects capture. Neither state weakens click authorization.
- **P2.40 – Bounded monitoring:** Re-observation uses bounded exponential backoff, same target package/window validation, lifecycle cancellation, and stops on completion or invalid foreground.
- **P2.41 – CONTINUE:** CONTINUE is a distinct AI action. It is only executable in `AD_PAUSED`, with an explicit resume label and the existing freshness, target, live-node, foreground, and final authorization checks.
- **P2.42 – SDK and home recognition:** Adds the observed TikTok `TTRewardExpressVideoActivity` class. Fruit Blast `MainActivity` is classified as `GAME_HOME`; this state is non-actionable. A transition from a known SDK Activity to the host Activity is classified as `AD_COMPLETED`.
- **P2.43 – Misclick recovery:** Automatic BACK is limited to Play Store (`com.android.vending`) and known browsers (`com.android.chrome`, `com.android.browser`), with a maximum of two attempts. Recovery completes only after the Fruit Blast package and active application window are verified. After return, the service waits for a genuine window-state event before rebuilding Activity identity and restarting ad monitoring; it does not synthesize an Activity class from a null event.

## Regression coverage

Unit tests cover:
- EMPTY vs FAILED foreground-window retrieval and capture-only fallback.
- Bounded monitoring cycles, backoff, reset, and rejection of UNKNOWN/non-target states.
- CONTINUE parsing, paused-state classification, explicit resume labels, and action allowlisting.
- TikTok SDK recognition, GAME_HOME recognition, and AD_COMPLETED transition.
- Play Store/browser recovery, rejection of unrelated external packages, bounded BACK attempts, and verified target return.
- Cross-policy regression: SDK ad → external browser/Play Store → verified Fruit Blast return → fresh ad/home classification → action allowlist.

## Required verification

Run the repository CI command:

```bash
gradle :app:testDebugUnitTest
gradle :app:assembleDebug
gradle :app:assembleDebugAndroidTest
```

A passing unit suite does not replace device validation. On the Xiaomi/MIUI device, verify:
1. TikTok reward ad opens and is classified as an ad.
2. A paused ad resumes only through CONTINUE.
3. Ad completion returns to `MainActivity` and is classified `GAME_HOME` / `AD_COMPLETED`, with no click.
4. Misclick to Play Store and Chrome/Browser sends at most two BACK actions.
5. Return to Fruit Blast waits for a real window-state event and resumes monitoring only after fresh Activity identity is observed.
6. Any UNKNOWN package, stale frame, failed window retrieval, mismatched window ID, or unverified target results in no click.

## Explicit limitations

- CI and device results must be reported from actual runs; this document does not assert that either passed.
- The regression test composes the pure classifier, execution, and recovery policies. It is not an Android UI end-to-end test.
- External destinations other than the explicitly allowlisted Play Store and browsers intentionally abort automatic BACK recovery.
