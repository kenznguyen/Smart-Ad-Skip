# P2.31 – Process Identity and Watchdog Hardening

## Binding generation

Each bind creates a new monotonically increasing generation and a distinct ServiceConnection instance. Every callback captures that generation; callbacks from an older connection are ignored. Requests carry the generation and responses echo it. Pending requests are resumed only when both generations still match.

## Process identity

The isolated service creates a random process-session UUID at process startup. HELLO establishes the session only when the response generation matches and the PID is positive, differs from the app process, and has a readable Linux /proc start-time identity. Every later response must match the active generation, PID, session UUID, and process start ticks.

## Watchdog termination

The watchdog snapshots generation, PID, session UUID, and /proc start ticks. It revalidates all four against the active remote session and re-reads /proc start ticks immediately before Process.killProcess, while holding the runtime state lock. A stale generation, replaced process session, PID change, missing start identity, or changed start time fails closed.

The state lock prevents this proxy from installing a new binding/session between identity validation and the kill operation. Android's public Process.killProcess API is PID-based rather than pidfd-based, so the final kernel operation cannot provide a mathematically atomic PID-reuse guarantee against an unrelated OS-level process exit/reuse in the tiny interval after the /proc recheck. The added session and start-time checks materially narrow and detect stale identity, but do not claim pidfd-grade atomicity.

## State consistency

Remote loss, successful handshake, load completion, watchdog termination, and close invalidate or establish remote/PID/session/readiness state together. A late LOAD response cannot restore ready after its binding generation or process session changes. Pending requests retain their originating generation and are failed on active-session loss.

## Tests and verification scope

NativeProcessSessionPolicyTest covers stale generations, invalid/main-process PID handshakes, changed process sessions, watchdog generation/PID/session mismatches, and PID reuse through changed /proc start ticks. Existing lifecycle tests continue to protect native single-flight ownership.

These are deterministic unit tests of the policy boundary. Android ServiceConnection callback injection, actual Binder death/reconnect, and concurrent OS process termination still require Android instrumentation/device validation; CI alone does not prove those platform races.
