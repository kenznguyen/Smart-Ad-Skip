# P2.34 – Watchdog Kill / Binder Reconnect Race Integration Testing

## Scope

Adds an Android instrumentation scenario against the real manifest-declared isolated
`:qwen_native` service. It captures a watchdog identity snapshot for process session N,
kills that process to trigger Binder death and Android auto-reconnect, then releases the
old watchdog only after session N+1 has completed HELLO.

## Assertions

- Process death is delivered through the actual Android ServiceConnection.
- The same bound connection reconnects and HELLO reports a different process-session UUID.
- The old watchdog's captured generation/PID/session/`/proc/<pid>/stat` start ticks are
  checked by the production `NativeProcessSessionPolicy.mayTerminate` gate against the
  current session. It must return false after reconnect.
- The newly connected process remains alive and answers another HELLO after the stale
  watchdog decision.
- Existing P2.33 instrumentation retains deterministic held-reply coverage for late
  callbacks and timeout/reconnect ordering. Existing production proxy single-flight
  mutex and native process ownership paths are unchanged.

## Device execution

Run on a physical ARM64 Android device or ARM64 emulator, API 26+:

```bash
gradle :app:connectedDebugAndroidTest
```

The hosted GitHub Actions workflow compiles and uploads the instrumentation APK; its
standard runner does not attach an Android device, so a green CI compile is NOT evidence
that device instrumentation executed. Record device model, API level, ABI, test count,
and test result separately when the command is run on hardware.

## Test boundary

The race test exercises a real isolated-process kill, Binder death, reconnect, session
handshake, and the exact production watchdog authorization policy. The instrumentation
test deliberately releases a captured stale watchdog decision after reconnect; it does
not invoke the private production watchdog scheduler itself. No production watchdog,
single-flight, timeout, or JNI ownership behavior is modified in P2.34. Existing P2.33
timeout and late-reply tests use the controllable Messenger endpoint and remain
instrumentation-only until run on a device.
