# P2.38 – Accessibility Window Retrieval Compatibility

## Changes
- Declare flagRetrieveInteractiveWindows in the accessibility service XML and enforce/log the runtime service flag on connection.
- Log rootInActiveWindow and getWindows() independently, including retrieval result, count, active count, root package and window ID.
- Distinguish a verified target root with an empty/unavailable window list from a root belonging to another package.
- Permit screenshot capture only for a verified target root when OEM firmware withholds the interactive-window list. A non-empty list still requires a matching active application window.
- Keep Result.isValid strict: root-only fallback is never click-valid. Existing live node lookup and final click gates continue to require a fully verified active application window.

## Device validation required
Hosted CI can compile the unit and instrumentation tests but cannot establish Xiaomi/MIUI runtime behavior. On the target Xiaomi device, collect logs for interactive_windows_capability, root_active_snapshot, interactive_windows_snapshot, and foreground_window_diagnostic. Verify that Fruit Blast root + empty list becomes root_verified_windows_unavailable and capture-valid only; a root package such as System UI, launcher, Termux, or SmartAdSkip remains rejected. Confirm click_valid=false in the root-only fallback case.
