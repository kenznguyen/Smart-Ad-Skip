# P2.28 – Native process isolation and watchdog recovery

## Process boundary

- The Accessibility service and dashboard remain in the application process.
- `NativeInferenceProcessService` runs in the dedicated Android process `:qwen_native`.
- Only that process loads `libsmartadskip_qwen` and owns llama.cpp, MTMD, model/context, sampler and JNI resources.
- The main process sends immutable frame data over Messenger IPC. Native output returns as a decision payload; existing shared safety checks, foreground validation, live Accessibility-node matching and final click authorization remain in the main process.

## Timeout and ownership

- The proxy uses the existing decision timeout. Cancellation of an in-flight IPC inference terminates only the dedicated native process.
- The main process never clears a local JNI slot or assumes that coroutine cancellation stopped native code.
- Android process death destroys the native address space and all resources owned by that process. A fresh service process must reconnect and load the model before another inference is accepted.
- The existing single-flight screenshot/frame gate remains unchanged. The decision engine still returns WAIT on timeout/busy/failure.

## Watchdog recovery policy

- Healthy native process: keep running.
- Inference exceeding the configured inference timeout: terminate the native process; do not start a concurrent inference.
- Process disconnect: allow a bounded restart subject to a cooldown.
- Restart budget exhausted or process PID unavailable: fail closed and refuse further inference.
- Intentional service shutdown does not count as a watchdog restart.

## Validation

- Unit tests cover healthy-process retention, stuck-process termination policy, bounded restart/cooldown, and fail-closed behavior.
- CI verifies JVM tests and debug APK assembly.
- Physical-device validation is intentionally not part of this change.
